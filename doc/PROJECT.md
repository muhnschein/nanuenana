# Nanünana

*Unofficial warning app for Sailfish OS, for Jolla's Harbour store.*

## What this is

- Shows official warnings for saved places and, with setting on, current location. Germany first: Bundesamt für Bevölkerungsschutz und Katastrophenhilfe (BBK), `https://warnung.bund.de/api31`, carrying MoWaS (civil protection), police, DWD (weather), LHP (flood).
- Alerts by notification: per category a lowest level, all-clear, optional every update, failure after 30 minutes without a successful check.
- Honest about limits: unofficial, can be late, checks only while running.

## What this isn't

- **Not official, not a replacement.** Sirens, cell broadcast, radio, authorities come first; app says so on first start, home, place, warning, About.
- **No push, no server of ours.** App polls source itself. No daemon, no autostart: closed app = no alerts (Harbour allows no background service). Later option, owner's go given 2026-11-26: collecting server (KDE FOSS Public Alert Server) for countries whose sources need one.
- **No tracking.** No account, no analytics. Position never leaves phone, never stored on disk.
- **No editing of warnings.** Issuer's text unchanged; no machine translation.
- **No other store, no other architecture.** Harbour, aarch64, Sailfish OS 5.2+.

## Where offered

`policy.rs`: `SUPPORTED` = `DE`. `BLOCKED` = `RU`, `BY`, `IR`, `KP`, `SY` (owner, confirmed 2026-11-26): never offered, wins over `SUPPORTED`. Also never: territories under Russian control outside Russia (Transnistria, Abkhazia, South Ossetia, occupied parts of Ukraine); needs outlines once Moldova, Georgia or Ukraine get support. Other sanctioned countries: not targeted.

Order of countries: EU first, starting Germany, then rest of world. Ukraine and Israel: app must send user to official air-raid channels first; design board `AirRaidNotice`.

Current location outside Germany (nearest listed place over 25 km away): row replaced by one line saying Germany only. No warnings shown, nothing requested.

## Source: BBK

- `GET /dashboard/{district}0000000.json`: warnings of one district (`district` = 5-digit Kreis key). Entry: `id`, `payload.version`, `payload.data` (`headline`, `provider`, `severity`, `msgType`), `i18nTitle.de`, `sent`, `expires`.
- `GET /warnings/{id}.json`: CAP-like detail, one `info` block per language (`de`, `de-LS` easy German, `en`, …).
- `GET /warnings/{id}.geojson`: area, `[lon, lat]`.
- Request tells service district only: never place, radius or position.
- Level from CAP `severity`: Extreme 4, Severe 3, Moderate 2, rest 1. Category from `provider`, else id prefix (`mow`, `pol`, `dwd`, `lhp`).
- Weather icon by kind of weather, from word in issuer's German headline, first match in this order: GEWITTER (storm), SCHNEE (snow), GLÄTTE/GLATTEIS/FROST (ice), NEBEL (fog), REGEN (rain), BÖEN/STURM/ORKAN/WIND (wind), HITZE/UV- (heat). No known word → plain cloud, never a wrong kind. BBK event codes (`transKeys.event`) not used: `eventCodes.json` gives picture file only, no meaning. Other categories: one icon each.
- One dashboard request per needed district per check. Detail and area fetched once per `(id, version)`, cached in `cache.json`, dropped when warning leaves all dashboards.
- Lenient parsing: bad entry skipped, rest kept. Answer over 16 MiB refused. HTTPS only.

## Places

- Place = name, district, centre, distance 1–25 km or whole district (`km` 0). Name is location's name; no custom names (owner).
- Bundled list `crates/nanunana-core/data/de-places.tsv` (name, district, lat, lon, postcodes), `de-districts.tsv` (code, name): about 14 500 places, 400 districts. Search runs on phone; typed text sent nowhere. Hits: name starting with typed text first; same name → place with more postcodes first (city before village of same name). Typed part marked in hit name; found on folded text (case, umlauts, ß), so `mun` marks `Mün`.
- Generated by `tools/places.py`, run in folder holding both downloads under their upstream names (`zipcodes.de.csv`, `plz_geocoord.csv`); writes both lists:
  - GeoNames postal codes for Germany (CC BY 4.0, geonames.org), as CSV of github.com/zauberware/postal-codes-json-xml-csv (`data/DE/zipcodes.de.csv`).
  - Delivery postcodes: github.com/WZBSocialScienceCenter/plz_geocoord `plz_geocoord.csv` (postcodes of Destatis Gemeindeverzeichnis, Apache-2.0). Used as filter only: GeoNames also lists bulk-recipient postcodes (companies, offices); rows outside delivery postcodes and organisation names dropped.
  - District name without kind gets one: town holding over half its postcodes → "Kreisfreie Stadt", else "Landkreis".
- Distance place: districts asked = own plus districts of every listed place within distance + 10 km. Warning counts when its area comes within distance of centre; no area known → counts (fail open). Whole district: every warning of own district.
- Current location: pseudo-place id 0, 2 km, named after nearest listed place. Position asked once per check (`PositionSource.update()`), kept in memory only. Fix older than stale limit → "no position since", last warnings stay with that note.

## Alerts

`alerts::decide`, pure: seen map + sightings + settings → notices.

- New warning at or above category's level → notice. Level rises to or above it → notice. Other change → notice only with "every update".
- Warning gone or cancelled, after an alert for it → all-clear notice (setting).
- First check of a place is quiet: existing warnings listed, not alerted.
- Check incomplete (a district failed) → nothing counts as gone.
- No successful check for 30 minutes → one failure notice (setting), cleared by next success.
- Stale = never checked, last check failed, or older than 2 × interval + 60 s. Stale place: error colour, "Warnings may be missing", never "No warnings".

## Architecture

```
Silica QML (pages, cover, notifications, BackgroundJob, PositionSource)
        |  App singleton: state and settings as JSON, methods, signals
nanunana-qt (qmetaobject-rs, C++ start-up glue; no logic)
        |
nanunana-core (no Qt): BBK parser, places, geometry, alert rules, engine, store
        |  HTTPS (ureq, rustls, bundled roots)
warnung.bund.de
```

- QObject on GUI thread only. `App.check()` runs `Engine::refresh` on a thread, answers by queued callback, then `checked(notices)`.
- Engine takes time (`now_ms`) and network (`Fetch`) as arguments: tests use fixed clock and canned answers. `--qml-check` mode never opens a socket (`Canned`, folder from `-D`).
- State `state.json` (places, settings, seen warnings, per-district results), cache `cache.json`, both in app data folder, written via `.part` + rename.
- Checking: `Nemo.KeepAlive` `BackgroundJob` at 5, 10, 15 or 30 minutes, also from sleep; `finished()` after every check. Only while app runs.

## Replay

Phone tests need warnings on demand; service has none to order. Same RPM tested and shipped: no test build.

- Start with `NANUNANA_REPLAY=NAME` → answers from `<data>/replay/NAME/`, no socket. Files named as service names them: `{district}0000000.json`, `{id}.json`, `{id}.geojson`.
- Own state in `<data>/replay/NAME/state`: real places, settings, seen warnings untouched.
- Name: letters, digits, `-`, `_`, at most 40. Other value or missing folder → every check fails, shown as failed. Never falls back to live service, never "No warnings".
- Replay never looks real: box "Test data · These are not real warnings." on places, place, warning; first cover line; every notification title starts "Test data ·".
- Next state = swap files of the set, then check again (new warning, update, all-clear).
- Sets in `tests/replay/`, not in RPM; pushed to phone by test run. `weather` (one warning per weather icon), `alert-1` → `alert-2` → `alert-3` (nothing, new fire warning, its all-clear): made up, in service's format, issuer texts invented.
- Real answers: `tools/replay.py record DISTRICT... > SET.tar` (dashboards plus detail and area, bytes as sent), `tools/replay.py archive DISTRICT ARCHIVE_ID > SET.tar` (past MoWaS warning from `archive.mowas`, dashboard entry composed from it). Set leaves as tar on stdout, unpacked into set folder. Run where `warnung.bund.de` is reachable.

## Platform

- Sailfish OS 5.2+, aarch64, Qt 5.6, Silica. Rust 1.95, cross-built against 5.2 SDK.
- Harbour validator is authority; CI runs it on every RPM (`tools/ci/check-rpm.sh`). Rules the design leans on:
  - Files only under `/usr/bin/harbour-nanunana`, `/usr/share/harbour-nanunana/`, desktop file, icons.
  - Links only: libc, libm, libpthread, libdl, librt, libgcc_s, libstdc++, Qt5 Core/Gui/Qml/Quick, libsailfishapp. Rest static Rust (TLS: rustls, no OpenSSL), no RPATH.
  - QML imports only from Harbour's allowed list: `QtQuick`, `Sailfish.Silica`, `QtPositioning`, `Nemo.Notifications`, `Nemo.DBus`, `Nemo.KeepAlive`; private module `Nanunana`.
  - `X-Nemo-Application-Type=silica-qt5`: booster `dlopen()`s binary, so `main` is exported (`build.rs`); TLS segment aligned 128 for libhybris.

## Words on screen

- `qsTrId()` with `//%` engineering English; counts as one `%n` plural. English and German catalogues.
- Levels: Information, Warning, Danger, Extreme danger (1–4). Categories: Civil protection, Police, Weather, Flood.
- Times: clock today, weekday + clock within six days, date + clock beyond.
